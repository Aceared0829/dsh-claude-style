# D7. 对外一个插件，内部是 monorepo

- **取代**：D8、D18、D46

## 背景

行为层与外观层依赖同一套宿主定位点、弹层部件与刷新机制，浏览器半边与宿主半边又各自需要不同的构建与验证边界。使用者要的是一次安装拿到全部效果，维护的人需要按职责把代码分开存放。

## 决定

- 对外只发布一个插件，使用者一次安装即拿到行为与外观两部分。
- 仓库内部按职责分包：浏览器半边、宿主半边、两半共用的契约、资源与清单生成、验证工具。一段新代码放进哪一包，由它被谁依赖决定。
- 两半共用的常量、路由名、偏好键与默认值只声明一处，由契约包持有，两侧按包名引用。
- 只想要行为、不要外观的入口是外观设置里的配色与字体；每个接管宿主界面的功能另有自己的开关。
- 包内仍按功能分目录，一个功能的脚本与样式放在一起；多个功能共用的部件单独成层。
- 文件行数与重复代码的停止线按包内路径执行，覆盖全部脚本。

## 后果

- 行为层随外观一起安装，无法脱离这个插件单独使用。
- 工作区配置与包之间的引用多出一层；跨包的路径改动牵动整个仓库，必须与逻辑改动分开提交。
- 拆开之后每个包各自的构建与验证边界清楚了，共用声明也不必再逐键核对。

## 重审条件

- 出现第二个真实使用者需要单独依赖其中某一包时，把它独立发布。
