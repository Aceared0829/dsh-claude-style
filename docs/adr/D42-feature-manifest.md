# D42. 功能清单、开关与按需加载

- **取代**：D13、D29、D39

## 背景

功能各自记住自己的安装次序、样式表先后、设置页开关行与核对范围时，加一个功能要在好几处同时添上一笔，漏掉的那一处只在运行时才显出形来。页面启动时整份客户端包一起求值，首屏用不到的功能也占着启动阶段的主线程；而功能之间又要能读到彼此，读不到的东西必须在写的时候就报出来，不能等到运行时拿到空值。

## 决定

- 每个功能把自己的全部事实写进一份清单：安装次序、是否延后、依赖的宿主契约、要读的其他功能句柄、样式表与它在整张样式表里的先后、拥有的设置页开关行、覆盖它的核对用例、对上游的让位、中英文描述。加一个功能只加一个目录。
- 每个功能二选一地声明：挂在哪个偏好键上，或者一句不设开关的理由。两者都写、都不写、或声明的键不在偏好缺省表里，都由类型检查和构建拒绝。
- 开关的语义是「关掉等于宿主原样」：关掉就运行这个功能自己的拆除，打开就重新安装，全程不刷新页面。几个功能可以共用一个开关或同一项选择的不同取值。
- 只让首屏可以缺席的功能延后。首屏就要改写宿主界面的功能留在主产物，否则页面先露出宿主原样再被改写。延后的功能自己的模块单独成块，页面被接管之后请求；块到达之前读它的功能把它当作缺席，块到达而这一代已经结束就不再安装。
- 功能之间的依赖由类型检查把关：功能模块只看得见自己声明的句柄，没有声明的读取在类型检查时被拒绝，不用运行时判断兜底。
- 记录次序、登记目标元素、订阅页面变化一类的事留在功能里，不进清单：清单只放数据，把同一件事记两遍正是这份清单要消掉的东西。
- 构建从清单汇总安装次序、样式表拼接次序、设置页的开关行、核对范围与对上游的让位，各处不再各写一份。

## 后果

- 清单的形状要稳定；样式表的先后被写成排位，插入一张新样式表要挑一个空位。
- 延后的功能比主产物晚到一次请求，到达之前相关界面没有反应；主产物与块的模块归属要反复推算到没有模块被两边同时携带。
- 关掉一个功能要求它的拆除能在运行中途完整交还宿主界面，代价是每个功能都要为开关打开与关闭两种情形各写一遍核对。

## 重审条件

- 加载器提供插件内的异步分块或资产地址时，延后的模块改走加载器的机制。
- 清单之外的事实反复被别的功能需要时，才把它收进清单；订阅的声明在出现需要它才能判定的行为时再进清单。
