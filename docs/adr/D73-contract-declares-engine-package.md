# D73. 一个偏好一条声明，引擎自立一包

- **取代**：D7

## 背景

仓库内部按职责分包，两半共用的常量由契约包持有。这条方向在偏好上没有走完：一个偏好要在契约的缺省表、浏览器半边的取值常量、`Prefs` 接口、取值集合表、页面镜像的属性名单、宿主半边的设置结构上各写一遍；加一个偏好或改一处取值要同时改完，漏掉的那一处只在运行时显出形来。浏览器半边同时长出一层与宿主直接打交道的机制——观察总线、帧管线、宿主访问、样式表挂载、延后块的加载、调度器、偏好绑定——它们与外观无关，却和皮肤代码住在同一层，反过来还要认识具体功能。

## 决定

- 对外只发布一个插件：使用者一次安装即拿到行为与外观两部分。只想要行为、不要外观的入口是外观设置里的配色与字体。
- 仓库内部按职责分包：浏览器半边、宿主半边、两半共用的契约、引擎、资源与清单生成、验证工具。一段新代码放进哪一包，由它被谁依赖决定。
- 一个偏好在契约模块里只有一条声明：键、类型、缺省值、取值集合、文本上限、旧值迁移。`Prefs` 类型、取值集合、浏览器半边的取值常量、页面镜像的默认、宿主半边的设置字段全部从这张表推导；取值集合只写一次，拼错的取值由类型检查拒绝。
- 宿主半边的设置字段保持宽松：字段接受字符串、布尔值与字符串数组，取值集合只在浏览器半边收敛，一个旧值永远不使宿主拒绝启动这个包。
- 引擎自立一包（`packages/engine`）：与宿主直接打交道、与外观无关的机制住在那里，浏览器半边与宿主半边各取所需。它随构建打进产物，不单独发布。
- 引擎不认识皮肤：属性前缀、包名、功能句柄表、调度器的重画来源、账户身份与模型文案由皮肤提供，或留在皮肤一侧。
- 依赖方向由构建检查：引擎不得导入皮肤的功能、主题与皮肤常量。
- 包内仍按功能分目录，一个功能的脚本与样式放在一起；多个功能共用的部件单独成层。两半共用的一份机制只在引擎里写一次。
- 文件行数与重复代码的停止线按包内路径执行，覆盖全部脚本。

## 后果

- 加一个偏好只改三处：契约表里一条、用到它的功能、功能自己的设置行。
- 引擎的接口只有一个使用者时，形状缺少反例校验，改动方向由契约测试与真实页面兜住。
- 移动文件与改逻辑分开提交，移动那一次要整份读一遍 diff。
- 放弃的方案：让每个功能自己写下它读的偏好、取值与宿主接口（代价是同一条假设被重复写下，宿主与契约改版的影响面要重新收集）。

## 重审条件

- 出现第二个使用这套机制的插件时，引擎改为单独发布的包，接口按两个使用者的需要定形。
- 宿主提供主题扩展点或页面变化的统一订阅时，引擎里对应的那部分改为接入宿主的。
