# D66. 测试分层

- **取代**：D45

## 背景

测试要回答的问题分属不同的层次，代价差别很大：单元层在秒级给出答案，冒烟与行为层要起浏览器、等页面稳定。此前把这些检查堆在一条通道里，改一个文件也要付出整条通道的等待。断言写成钟点与像素量值时，同一份代码在忙碌的机器上失败，失败之后只剩放宽断言这一条路。

## 决定

- 测试只有一个入口。发起一次运行就是发起整套判定，各处不再另开自己的脚本与通道。
- 测试按「读什么」分档与分批：不读构建产物的检查与单元层同批起跑，读构建产物的浏览器层在构建写完之后同批起跑，一批的耗时是其中最长的一个。一次运行只覆盖当前改动到达的范围，需要更宽的范围时按名字点名。
- 每一层只回答它能回答的问题。单元层回答纯逻辑与顺序；冒烟回答产物能否装载、功能的安装与拆除是否成对、开关能否翻转、延后取回的块能否到达；行为层在真实宿主上回答用户能看见的结果。
- 断言读用户可观察的结果与页面自己记下的序列：属性、文字、元素在不在、滚动终点，以及页面在帧回调里记下的位置序列满足的不变式。钟点阈值、帧数与单个像素量值都不进断言。
- 两种时长本身就是被测的行为，作为例外进断言：产品规格写明的一段时长（说法锁住一秒、加载点十秒一换），由页面用自己的时钟记下每一刻，边界取自规格；性能场景量的就是耗时，比较同一回合在两个会话长度上的比值，并给出上限。
- 等待某个状态出现或等页面静置时，限时只用来让卡住的等待按名字失败。
- 动效只在页面记下的序列上判定：序列单调、中间经过多个不同的值、终点等于目标。曲线的形状留在单元层。
- 静置的判定是页面上的全部有限动画都已结束，且页面在连续若干帧里没有新的变化。动画中间的状态从动作开始逐帧记录到静置，断言读这段记录；能暂停的动画用暂停与定位时刻读取。
- 行为层只对宿主最新发布的版本给出结论，不论它挂在哪个发行标签下：版本由 `packages/testing/host-version.cjs` 按注册表的发布时间读出，云端安装的就是它；本机的宿主不同时，行为层不给结论，一次运行的答案是「未判定」，不记入已完成的判定。宿主发布新版本后，行为层在遇到它的那一次云端运行里直接面对它。
- 需要数帧的地方改读这些帧覆盖的时间跨度，阈值写成毫秒，同一段墙上时间在每秒画帧少的显示上得到同样的判定。
- 外观用计算值快照对照：快照在真实宿主上读取，走查经过的每个页面形态各读一份，只收与字体无关的属性。
- 检查按「谁的输出」分两档：仓库自己的行为与契约阻断合并；宿主输出的精确记录（外观快照、从未匹配的选择器清单）作为观察，写入 `observations.json` 与运行摘要，与记录不同时报告而不阻断，记录由人读过观察后更新。
- 闸门在本机只属于推送之前那一段：取覆盖这次改动的最小集合，在后台发起，一次运行只服务这一次推送。完成的判定以推送后云端的结果为准，本机的结论不作数。
- 一次运行只对它读过的那棵树成立，运行期间继续改动会让这次结论过期。行为层的失败默认是产品缺陷，放宽断言的改动要在提交说明里写出旧断言误判了哪一种产品行为。

## 后果

- 行为层需要本机装有宿主，没有的机器只能编辑，推送交给有宿主的机器。
- 分层之后每一层各有自己的启动代价，窄范围的运行读不到改动之外的回归。
- 外观快照绑定字体与渲染平台，本机生成的快照只供参考。
- 放弃的是把全部检查塞进同一次运行、以及用钟点衡量快慢这两种做法；换来的是同一棵树每次得出同一个答案。

## 重审条件

- 宿主提供官方的插件测试环境时改用宿主的。
