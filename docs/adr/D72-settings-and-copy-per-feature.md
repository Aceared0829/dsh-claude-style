# D72. 清单登记设置行，界面文案随功能

- **取代**：D42、D13、D29、D39

## 背景

功能把自己的全部事实写进清单，设置页的开关行也由清单汇总，登记分散的问题因此收敛。剩下两块没有跟着走：带取值的行、带预览卡片的行写在设置功能的文件里；界面文案与模型文案共用一份文档，键与英文兜底写在调用处。于是一个功能的选项要改设置功能，排位分写两处（清单里的开关行、设置页里的选项行各写一个数），让位状态由设置页逐个推算，文案的键写错时界面静默显示兜底文字。

## 决定

- 每个功能把自己的全部事实写进一份清单：安装次序、是否延后、依赖的宿主契约、要读的其他功能句柄、样式表与它在整张样式表里的先后、设置行、覆盖它的核对用例、对上游的让位、中英文描述。加一个功能只加一个目录。
- 每个功能二选一地声明：挂在哪个偏好键上，或者一句不设开关的理由。两者都写、都不写、或声明的键不在偏好表里，都由类型检查和构建拒绝。
- 开关的语义是「关掉等于宿主原样」：关掉就运行这个功能自己的拆除，打开就重新安装，全程不刷新页面。几个功能可以共用一个开关或同一项选择的不同取值。
- 只让首屏可以缺席的功能延后。首屏就要改写宿主界面的功能留在主产物。延后的功能自己的模块单独成块，页面被接管之后请求；块到达之前读它的功能把它当作缺席，块到达而这一代已经结束就不再安装。
- 功能之间的依赖由类型检查把关：功能模块只看得见自己声明的句柄，没有声明的读取在类型检查时被拒绝。
- 设置行按归属登记：一个功能在自己的清单里登记它的每一行设置，每行绑定一个偏好键，写明控件种类（开关、分段、预览卡片、定制）、所在标签页、排位、文案键，以及它依赖的其他行（`requires`、`windowsOnly`、从属上一行）。
- 取值从偏好表读（D73）：分段控件与预览卡片的选项不再各写一份取值集合，清单只写每个取值的文案键。
- 带预览或定制的控件是功能目录下的 `<功能>.settings.ts`：控件是代码，放在它服务的功能旁边；构建按功能收集这些模块，收进设置页那一块。
- 界面文案是功能目录下的 `<功能>.copy.json`：每个键一对中英文。构建把它编进该功能的模块——主产物里的功能进主体，延后加载的功能进自己那一块。
- 代码只写键：调用处只写键，英文兜底不再写在调用处；键的类型由构建从该功能的文案文件生成，写错的键在类型检查时被拒绝。
- 模型文案仍然是一份数据文档（D5）：`model-descriptions.json` 只留模型家族、档位与厂商的规则。
- 清单仍然是数据：构建在 Node 里求值清单，组件模块与文案只在浏览器里求值，清单引用它们的模块名，构建核对文件存在。
- 构建从清单汇总安装次序、样式表拼接次序、设置页的行、核对范围与对上游的让位，各处不再各写一份；并拒绝没有登记的设置行、同一个偏好被两行绑定、指向不存在的控件模块、文案键在所属功能的文案文件里不存在、两份文案缺一种语言。

## 后果

- 加一个设置行只改功能自己的目录；设置页不随功能增多而变大。
- 设置页的渲染收成一个按标签页与排位装配的页面，外观由清单与控件模块决定；视觉变化要人工核对浅色与深色两种配色。
- 界面文案随功能进入产物后，首屏不必等文案文档到达：界面文案在首屏就有，模型文案到达时只重画模型选择器。
- 清单的形状要稳定；样式表的先后写成排位，插入一张新样式表要挑一个空位。
- 延后的功能比主产物晚到一次请求，到达之前相关界面没有反应；主产物与块的模块归属要反复推算到没有模块被两边同时携带。
- 关掉一个功能要求它的拆除能在运行中途完整交还宿主界面，代价是每个功能都要为开关打开与关闭两种情形各写一遍核对。
- 一份文案被两个功能用到时，要么各写一份，要么登记在设置功能里由两处按名引用。
- 放弃的方案：界面文案与模型文案继续共用一份文档（代价是一个功能的文案改动要动共享文档，键写错时静默回落）。

## 重审条件

- 加载器提供插件内的异步分块或资产地址时，延后的模块改走加载器的机制。
- 宿主提供插件内的文案读取接口或界面文案的翻译服务时，界面文案改为接入宿主的。
- 设置页的渲染由宿主提供统一表单时，清单里的设置行改为交给宿主的结构。
