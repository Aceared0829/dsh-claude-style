# D43. 依附宿主表面与宿主数据

- **取代**：D2、D17

## 背景

皮肤盖在宿主已经画好的页面上，宿主没有为它准备扩展点。宿主同时又掌握着一批皮肤正好需要的数据：可用的权限档位、它们的名称与说明、界面语言。皮肤若自己再写一份，两个来源会各自变化；若处处依附宿主，效果就受制于宿主没有承诺过的内部细节。

## 决定

- 宿主已经提供的数据以宿主为准：档位集合、名称与说明都从宿主读取，皮肤只决定这些数据怎么显示。宿主目录里没有的档位不出现，皮肤不另备一份名单。
- 档位名称跟随宿主当前语言下的原文；宿主没有给出译文的档位，皮肤才补一个自己的说法，内部标识不出现在界面上。
- 切换档位交给宿主自己的处理，皮肤不另实现一遍。
- 宿主已经提供的表面优先依附：宿主给出的插槽定位点、属性与角色标记能定位的地方，就按它定位；宿主没有开放扩展点的地方，效果以覆盖层实现，覆盖依赖的假设写进契约模块。
- 覆盖层依赖的假设逐处记录：现在靠什么撑着、坏了会怎样、期望的入口是什么。宿主放出对应能力时，该处改为接入宿主，并从契约模块里删掉被取代的假设。
- 扩展点不向上游争取：等待宿主自己开放，不以提交外部议题或合并请求的方式推动。
- 宿主半边只做页面做不到的事（资源、身份、路由、设置表单的配置），能在页面上完成的都留在页面。

## 后果

- 档位集合由宿主决定，皮肤无法决定取舍；宿主缺译文的档位，界面上会同时出现宿主给的说法与皮肤补的说法。
- 覆盖层的正确性取决于宿主没有承诺过的内部细节，宿主改版后要跑一遍才知道哪条假设失效；覆盖与真接入的差别只能靠契约测试与端到端通道兜住。
- 放弃的方案：皮肤自带一份完整的档位名单与名称，界面在任何宿主版本下都保持同一种样子。代价是档位集合跟着宿主变化，宿主缺译文的档位只能由皮肤临时补上。
- 放弃的方案：为缺扩展点的几处主动向上游提交扩展点。放弃之后只能等待，等待期间这些效果随宿主版本漂移。

## 重审条件

- 宿主开始接受外部的议题与合并请求，或者开放完整的主题扩展点时，重新考虑向上游争取扩展点。
- 宿主的档位目录直接给出本地化名称时，改为读取目录本身。
- 宿主原生支持档位图形、界面有了统一的档位图形语言时，再考虑画图标。
