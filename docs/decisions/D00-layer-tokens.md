# D00. 层级令牌：与宿主争高低的 z-index 只写在令牌里

- **状态**：已实施
- **分组**：构建与源码
- **关联**：D33、D51、D65

## 决定

- 皮肤写的 z-index 分两种：
  - 盒内次序：同一个盒子里兄弟元素之间的先后，写 -1 到 9 的字面值（自己内容之下的底色、滑块上的文字、输入卡片里几层行的叠放）。
  - 层级：要压过宿主在它周围画的东西时，读 `packages/client/src/theme/tokens.json` 里 `layer` 一组的令牌，每条带 `use`，按站在这一层上的东西命名：输入框里的控件 `--dsh-claude-layer-control`（10）、从输入框里挂出卡片的选择器 `-picker`（20）、窗口标题行 `-chrome`（30）、浮在一切宿主界面之上的卡片与菜单 `-float`（99999）、盖住整个窗口的界面 `-takeover`（2147483000）。
- 生成：令牌样式表多出一个不挂门的块，`docs/STYLE.md` 多出一张由同一份数据重写的层级表。
- 检查：
  - `scripts/css.mjs` 在语法树上拒绝令牌样式表以外 -1 到 9（以及 `auto`）之外的 z-index 字面值，并拒绝没有任何样式表读到的层级令牌。
  - `scripts/build-checks.mjs` 拒绝 `packages/client/src/` 的 TS 里写出 9 以上的层级（内联样式的 `z-index` 与 `zIndex`，在语法树上按类型读出，经常量与参数转手的同样算，`scripts/source-tree.mjs`）：浏览器半边给元素做标记，由样式表把它放到某一层。

## 理由

- 与宿主争高低的数值原先散在十来张样式表里（10、20、30、99999、2147483000），每个数都只有写它的那一处知道要压过谁；一张表把这些层排在一起，新加的界面挑一层或加一层，加层时表里看得见上下两层。
- 盒内次序只与同一个盒子里的兄弟相比，换个地方就没有意义，收进全局表反而让表里塞满互不相干的小数。

## 代价

- 盒内次序与层级的界线是 9：组件里需要第十层的叠放时，要么在组件里减层，要么把它当成一层写进令牌表。

## 重审条件

- 宿主公开自己的层级令牌时，与宿主比高低的几层改为在宿主那一档上加减，像配色那样分出宿主一档。
