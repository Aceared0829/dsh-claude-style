# D48. 文档流程

- **状态**：已实施
- **分组**：分发与流程
- **关联**：D42
- **现状**：决策一文件一条，索引由 `scripts/decisions-index.mjs` 从各文件的标题、状态、分组、取代关系与 `docs/decisions/retired.txt` 生成，持续集成核对它与文件一致；新决策以占位号 D00 起草，合并前由 `scripts/decision-number.mjs` 取号，持续集成拒收占位号；每个改动在 `docs/changes/` 下放一个结构化的小文件，`scripts/changelog.mjs` 把它汇编成 CHANGELOG 的 `[Unreleased]` 一节，发版时汇编成版本一节并清空该目录，持续集成核对这一节与文件一致；`scripts/lint.mjs` 管不需要构建的规则（停止线、Markdown 链接、决策编号引用、反引号里的仓库路径、功能模块的 ui、复制代码、文档数值的出处）；功能一览由 `scripts/features.mjs` 从各功能清单的 `description` 字段汇编进 `docs/FEATURES.md` 与 `docs/FEATURES.en.md`，持续集成核对；README 与设置说明仍手写；作用域、`:has()` 位置与令牌门已由构建检查（D51）

## 决定

- 准入门槛：改动按三层去向分流。一次性动作（移除、迁移、替换实现）只在 `docs/changes/` 与提交说明里留痕，不产生决策；能由工具强制的规则写进 lint 或构建检查，决策与 AGENTS.md 里只留理由；只有约束未来改动、且理由无法从代码与测试推出来的结构性选择才成为决策。预期不会有代码注释引用的题目，多半属于前两层。
- 决策一文件一条，文件名 `D<编号>-<英文短名>.md`，模板固定为：标题；状态（已实施 / 待实施 / 部分实施）；分组（索引里的分组名）；关联（取代了哪些编号也写在这里）；可选的现状（待实施与部分实施写明）；决定、理由、代价、重审条件四节。编号稳定，代码注释按编号引用；被推翻的编号作废、不复用。事故经过与演变过程写在提交说明里，不进决策文件。
- 合并纪律：新决策与旧决策内容重叠时，把旧决策仍有效的内容重写进新文件并作废旧编号，不允许补丁式并存；删除一条无后继的决策时，把编号记进 `docs/decisions/retired.txt`，一行一个，作废编号同样不复用。
- 取号时机：编号在合并时分配。草稿文件名 `D00-<短名>.md`、标题 `D00. <标题>`，正文照常；本地的 lint 与索引生成跳过占位号，持续集成拒收。合并前运行 `npm run decision:number`：脚本取现有编号与作废编号中的最大值加一，改写文件名、标题与全仓库的占位引用，并重建索引。
- 篇幅：「决定」「理由」「代价」「重审条件」四节都以要点列出，每条讲一件事，「理由」「代价」「重审条件」各不超过三条。「决定」一条一句约束、不超过三百字，一节合计不超过三千字；机制叙述属于代码注释，与代码的对应关系写在「现状」里，「现状」不超过六百字。一条「决定」里出现与标题无关的主题时，说明这条决策该拆成两条。
- 索引由脚本从各决策文件的标题、状态、分组、取代关系与 `docs/decisions/retired.txt` 生成，持续集成核对它与文件一致；索引里的一行由文件自己给出，没有第二处手写。
- 变更记录：每个改动在 `docs/changes/` 下放一个 `<短名>.json`，中英文写在一起，带日期、分组、组内次序与「是否影响外部契约」的标记；`scripts/changelog.mjs` 把它汇编成 CHANGELOG 的 `[Unreleased]` 一节，发版时用 `--release` 汇编成版本一节并把文件清空。CHANGELOG 里这两类小节都不手改，持续集成核对小节与文件一致。
- README：只留预览、安装、字体、皮肤中心交接与许可等手写部分；功能一览与设置说明放在 `docs/FEATURES.md`、`docs/FEATURES.en.md`、`docs/SETTINGS.md` 与 `docs/SETTINGS.en.md`，README 用链接指向它们。功能一览从功能清单（D42）的描述字段生成中英文两条目，夹在标记之间由 `scripts/features.mjs` 汇编。
- AGENTS.md 只留工作流与红线，决策里已有的规则只写编号；能由工具强制的规则写进 lint（`scripts/lint.mjs`）之后从 AGENTS.md 删掉。lint 管不需要构建的几条：停止线、Markdown 相对链接、注释与文档引用的决策编号、复制的代码（jscpd）与决策「决定」一节的篇幅；带单位的数值由 `npm run docs:numbers` 按需核对，不进闸门——`docs/STYLE.md` 的几何与时长与样式表逐字对应。构建检查（D44、D51）或冒烟用例盯住的规则不再进 lint。

## 理由

- 一个长文件里的长段落，读的人要花很多力气才找到要的那一条；每条一个文件、固定模板，改动与引用都更准确。
- 没有准入门槛时，任何改动都容易顺手写成决策，文件数只增不减；一次性动作的历史由 Git 与变更记录保存，决策文件不承担记事。
- 写作时取号会让并行的分支抢同一个号；合并时取号把冲突变成合并顺序，而新决策在合并前没有仓库外的引用，改写成本低。
- 中英文与 CHANGELOG 手工同步，容易漏、也容易和并行的会话冲突。

## 代价

- 生成的文件不能手改；脚本的格式要和现有 CHANGELOG 的格式完全一致。
- 占位号在持续集成里是一道额外检查；取号脚本的改写范围要和 lint 的引用检查保持一致。

## 重审条件

- 无。
