# D66. 测试的分档、单一入口与闸门的发起时机

- **状态**：已实施
- **分组**：分发与流程
- **关联**：D69、D40、D44、D46、D47；取代 D45

## 决定

- 所有测试由一个入口发起：`scripts/verify.mjs`（`npm run verify`）。同一工作树同时只允许一次运行（锁在 `.debug/verify.lock/`），结论按「树内容的散列 + 本次闸门集合」记进 `.debug/verify-cache/`，同一棵树上的再次请求直接读这份结论并注明是哪一次跑出来的，`--force` 才重跑；等待中的请求在锁放开后先查一次结论，并行会话因此排队而不是各起一套浏览器。
- 不带参数的请求是迭代期那一档：那批不需要构建的检查、构建，以及改动触及的单元测试。改动由 `git status` 从工作树在 `packages/client/src` 与 `packages/contracts/src` 下的路径读出，交给 `vitest related` 跑这些改动能到达的测试文件；工作树在这两处没有改动时跑整条单元通道。这一档不起浏览器，本机五秒上下出结果。
- 闸门按它读什么分批：那批检查、构建与单元测试同批起跑；冒烟与端到端通道读构建产物，在构建写完之后同批起跑。一批的耗时是其中最长的一个闸门，不再是各闸门相加。
- 各档由参数点名：`--quick` 走冒烟的快档（不含动效用例），`--case` 与 `--feature` 走冒烟里点名的用例并连带动效用例，`--full` 走整份冒烟，`--e2e` 与 `--scenario` 加上端到端通道，`--no-e2e` 把通道从任何一档里去掉；除迭代档外，各档都跑整条单元通道。整份冒烟与端到端通道的默认表一起才是一分钟以上的那一档。
- 冒烟的页面与端到端通道的场景互相独立：前者各有自己的上下文、标记与探针，按 `--jobs`（默认取本机核数与 6 之间的小者，至少 2）一起驱动，看动效的页面一次至多两个；后者为并发的每个场景备一份自己的临时 home，整条通道共用一个浏览器，而按 `--shard` 取的那一份切片逐条跑。怀疑读到被拖慢的帧时用 `--jobs 1`。
- 一次请求同时要整份冒烟与端到端默认表（`--full --e2e`）时先打印「请确认你正处于发布流程。」：这一对是云端的发布闸门。
- 结论只对它读过的那棵树成立：后台运行期间继续改动会让那次结论过期，要判断当前这棵树就用同一套参数再发起一次，命中已记录的结论即刻回答。运行期间 `npm run dev` 的重建换掉了构建产物时，这次运行不写下结论。
- 闸门的发起时机：本机默认不起闸门，一次运行只属于推送之前那一段，取覆盖这次改动的最小集合，在后台发起；云端只在推送到 master、pull request、合并队列与手工触发时跑，会话自己的分支不跑，完成的判定以推送后云端的结果为准。
- 单元测试（Vitest，浏览器模式跑在本机 Chrome 上）覆盖纯逻辑：弹簧曲线、气泡形状采样、折行分段、吉祥物状态机、偏好解析、观察总线的分发顺序（D40）、滚动主人的仲裁与接管（D41）。构建生成的模块（D36）在测试里由配置按同一份数据写到 `.debug/vitest/`，模块在测试中读到的动效令牌与页面上的一致（D65）。契约测试见 D44。
- 可运行的验证工具都住在 `packages/testing/`，共用一套浏览器接口：找本机 Chrome、开上下文与页面、关浏览器只有 `packages/testing/browser.cjs` 一处实现。冒烟跑在仓库自己的替代宿主页面上，用例表来自各功能清单（D42）；端到端通道起一个临时实例，模型由脚本化服务回答；在线探针对着一个已经在跑的实例量真实时序。
- 持续集成的构成、触发与分片见 D69：本机这一档与云端跑的是同一批闸门。

## 理由

- 迭代期反复跑的是同一批闸门。工作树只动了一两个文件时把整条单元通道跑完，等来的是与这次改动无关的测试，改一行的反馈要花掉整条通道的时间。
- 一批里的各个闸门互不相干：串行跑把最慢的一个的耗时加在别的上面，分批之后一次全量是一个批次的耗时加上最长的那条通道。
- 冒烟的页面与端到端通道的场景各自有自己的上下文与临时 home。一次只驱动一个时，花掉的是上一个的等待时间。

## 代价

- 结论按树内容复用，因此改动与闸门无关的文件（例如文档）也会让下一次请求重跑，`--force` 用来强制重跑一棵没有变化的树；排队意味着一次完整运行会挡住同一工作树上随后发起的请求。
- 并发的页面与场景争用机器。动效用例与逐帧断言读的是帧，同一台机器上另起浏览器或构建会让它们读到被拖慢的帧；这类失败要用 `--jobs 1` 重跑一遍才作数。
- 迭代档只回答工作树改动到达的测试，改动之外的回归要等 `--quick` 或更宽的档才读到。没有 Chrome/Edge 的机器起不了冒烟，这类机器只编辑，推送交给有浏览器的机器。
