# D3. 宿主选择器纪律

- **状态**：已实施
- **分组**：宿主边界
- **关联**：D9、D19、D43、D44

## 决定

- 定位宿主元素按这个优先顺序：宿主的稳定契约（`[data-slot]` 插槽定位点、宿主自己的 `data-*` 属性，见 D19）→ 皮肤自己按结构写下的标记 → 宿主文档里查到的宿主类名。
- 宿主 CSS 模块的类名形如 `<哈希>_<局部名>`，局部名是唯一稳定的那一段。这份映射写在 `packages/client/src/core/parts-table.ts`：一条目一个局部名，映射到皮肤自己的部件名。
- `packages/client/src/core/parts.ts` 在页面结构变化时读一遍宿主的类名，把部件名写进 `data-dsh-claude-part`（空格分隔的多个部件名）。样式表只按整词匹配：`[data-dsh-claude-part~="row"]`。
- 样式表里不再出现任何类名子串选择器；样式表要写的宿主锚点只有 `[data-dsh-claude-part~="…"]`、宿主的 `data-slot` 与宿主自己的 `data-*` 属性。
- 一个局部名在不同区域含义不同时，按区域分别登记：作曲区的 `row` 与会话里的 `row` 是两个区域的条目，互不牵连。
- 宿主的整页文字与角标角色（`title`、`headline`、`caption`、`mono`、`tagSystem`…）登记在整页区域，向 `<body>` 之下读取。
- 新增宿主元素时在 `parts-table.ts` 加一行；`scripts/css.mjs` 把样式表读到的每个部件名对到这张表，拼错或已退役的名字构建失败，而不是静默匹配不到。
- 皮肤自己的类名前缀 `dsh-claude-` 作为一个完整类词匹配（`[class^="dsh-claude-"], [class*=" dsh-claude-"]`），不再按片段匹配。
- 不覆盖会话进行时 `view-area` 部件的布局约定（`flex: 1 0 auto; min-height: auto`），它负责把输入框固定在滚动区底部。
- 全局链接颜色排除带 `link-button` 部件的链接：它们是自带文字颜色的填充或描边按钮（例如设置页的「充值」）。

## 理由

- 宿主类名里只有局部名稳定，而子串匹配会连带命中同一片段的其它元素：`row` 命中 `…_grow` 曾把输入框高度锁在 28px，`rail` 命中 `trailing`，`tag` 命中 `stage`，`title` 命中 `titleRow`、`titleCluster`、`subtitle`。改读局部名之后匹配是整词相等，这些都不再发生。
- 宿主改名时，部件不再被写出，对应规则静默；同一个名字在真实页面上是否还写得出，可以在页面里按部件名直接问。
- 部件是皮肤自己的属性，别的插件的类名不会被这些规则扫到，皮肤也不会因为别人取了相似的类名而改样。
- 界面文字随语言与宿主版本变化，因此仍不按文字匹配。

## 代价

- 多一次标记遍历：装机时走一遍页面，之后只走宿主新挂上的子树与类名变化的元素；一次全页遍历约 3.5ms（本机 7800 个元素、5200 个带类名的元素），因此它随结构变化运行，不随每一帧运行。
- 标记名与 CSS 的部件名要一致；`scripts/css.mjs` 的部件门禁承担这一条。

## 重审条件

- 宿主为这些区域提供稳定的 `data-*` 契约时，优先改读宿主的属性，`parts-table.ts` 里对应的条目随之删除。
