# D19. 宿主契约与构建编号

- **状态**：已实施
- **分组**：宿主边界
- **关联**：D3、D43、D44

## 决定

- 契约的字面与条目集中在契约模块的一张表里（D44）；契约测试按这份表逐条核对真实宿主，端到端环境搭好之前由冒烟检查的替代宿主页面复现（D66）。
- 插槽定位点：宿主渲染器保证每个插槽外面有一层按插槽名取的包装层，供外部定位；权限按钮按这层包装查找，跳过皮肤自己插进去的按钮。
- 控件标记：按宿主输入框的结构给控件写皮肤自己的标记属性，分别标记工具行里唯一打开 listbox 的按钮、提交区的主按钮（停止与提交按图标区分，排队与插话是同一个按钮换了文字）与权限插槽里的按钮。
- 弹层角色随开合写撤：宿主把文档里每个 `[role="menu"]` 当作占据前景的菜单，快捷键派发与模态层的判定都按它走。皮肤为量宽高而常驻在 `<body>` 里的弹层卡片，关闭时只是视觉上藏起来，所以这个角色要与开合标记同写同撤，卡片开着才持有；本就开时挂载、关时摘除的卡片不经过这一条。
- 构建编号：构建取产物内容的哈希写在 `<body>` 的属性上，页面跑的是哪一版以它为准；热重载替换插件代码而不重新加载页面，页面的加载时间说明不了代码版本。

## 理由

- 界面文字与哈希类名随语言、版本变化，结构与契约更稳定。
- 关闭的卡片若持有 `role="menu"`，宿主会把整套快捷键判给一个看不见的菜单。

## 代价

- 结构判断依赖宿主 InputBar 的现状，宿主改版时需要核对。
- 宿主按 `modalSelector` 判定快捷键这一侧，测试只查皮肤自己的不变量：关闭的弹层卡片不持有 `role="menu"`。

## 重审条件

- 宿主给这些控件提供自己的 `data-*` 标记时，直接读宿主的标记。
