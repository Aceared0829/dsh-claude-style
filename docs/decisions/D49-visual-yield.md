# D49. 让路：皮肤或 ds-bot 占用页面时收掉整套视觉，留下设置页与界面切换

- **状态**：已实施
- **分组**：功能
- **关联**：D12、D29、D30、D32、D33、D39、D40、D51

## 决定

- 页面属主有两个，属主判定回答「这一页现在归谁」：
  - 皮肤：皮肤中心在另一个皮肤作画时把皮肤 id 写到文档上，这个标记在即让路。
  - ds-bot 的 Bot 界面：启动清单里有它时，它的外壳组挂在页面上留下的标记即在让路，撤回给宿主自己的界面（它的 Agent 模式）时这个标记消失；它的浏览器半边晚于本主题运行，在它公布自己的注册表之前，由它存在本地存储里的模式回答，所以停在 Bot 界面的页面重新打开时本主题一帧也不先画。
  - 属主判定在启动时同步读一次，之后无论启动时是否让路，都由观察总线上的订阅（D40）跟随两处标记的真实变化；判定每次重算，不跨变化缓存。皮肤优先：两者同时在时页面归皮肤。
- 壁纸插件不是属主：壁纸画在外壳背后，本主题与它共存，配色选「跟随宿主」时弹层带上它的玻璃效果（D30）；配色留 Claude 时外壳画布不画、整窗铺一层画布色遮罩（D61）。
- 让路时：别的界面仍要用的那几样保留（设置表单的接管、模型文案与用户名等装载、偏好的采用），留下的功能按属主定：皮肤只留设置页；ds-bot 留设置页与界面切换（读者回到本主题的路）。不盖本主题的存活标记、不挂本主题的样式表、不跑调度器。让路期间采用偏好只更新偏好值、不往 `<body>` 写属性，因为表单随时可能应答，设置页的块也可能在让路之后才到（D39）。模块作用域的兄弟包样式表寄存照常运行，兄弟包的样式表不能等本皮肤。
- 界面切换自己的样子写在作用域归它自己的样式表里，构建把它们拼成另一张表单独发出（D51），由切换功能自己挂载与撤下，本主题的样式表离开时它不受影响。这张表只读宿主令牌与在任何画布上都可读的半透明色：代码一侧由本主题画宿主令牌，聊天一侧由 ds-bot 画。
- 切换只驱动 ds-bot 自己的模式：聊天一侧按它页脚回 Bot 界面的按钮，代码一侧按它账户菜单最后一组的 Agent 模式项，菜单在点击之后才渲染，所以在下一帧按、期间菜单不可见；当前模式读属主判定，从 ds-bot 自己的入口切换时切换同样跟上。桌面端它固定在窗口顶端那一行、侧栏列的右沿以内，位置由测量写入，侧栏收窄到放不下时隐藏起来、保留尺寸供下一次测量；网页上它在侧栏第一行（Bot 界面里是 ds-bot 自己的顶行，本主题下是品牌行、收起按钮之前）。
- 抢回页面时：写上本主题的存活标记与能力标记、重新采用偏好、挂样式表、装齐功能、装调度器；已在装的功能不重复安装。交给另一个属主时：先装上该属主留下而还没装的功能（启动即让路，或从一个属主换到另一个），再跑完其余功能的拆卸、撤掉本包在 `<body>` 上的全部属性与样式表。
- 宿主运行时收到的一次性拆卸仍是唯一的：先停属主观察，再跑完其余功能的拆卸，再停对话插件观察与偏好绑定。
- 能力标记与存活标记同时在 `<body>` 上出现，表示这一版能让路；皮肤中心据此才把本主题当作可选皮肤列出来，没有它的旧版本不会被选用。

## 理由

- 皮肤中心把标记注入服务端 HTML、ds-bot 的模式存在本地存储里，两者都让第一帧就有答案；而 D32 已经用同样的「信号 + 观察者」形状处理过另一个插件，重复发明一套形状不如沿用。
- 让路的粒度是整页而不是单个功能：只关掉功能表会漏掉样式表、无开关的功能、`adoptPrefs` 打在 body 上的属性，以及独立安装的调度器与座位键（D12 的隔离不等于整页交还）。ds-bot 的 Bot 界面同样接管侧栏、对话与输入框，两套覆盖叠在一起只会互相盖住。
- 收掉视觉不是卸载：读者的设置页与偏好必须继续在，别人的界面不该顺手删掉本包的东西；把模式交给 ds-bot 自己切换，两边各自记住的状态都不丢。

## 代价

- 让路期间整页惰性：设置页以宿主样式渲染，页面上的其他本包行为全部停摆；翻转会带来一次可见的重新挂载。
- 界面切换依赖 ds-bot 未承诺的类名、标记与菜单顺序（契约表里 `ds-bot.*` 各条），由端到端通道的 `dsBot` 场景对着固定版本核对；启动清单里有 ds-bot 而它的浏览器半边没能运行时，存下的模式若是 Bot 界面，本主题会一直让路，页面留给宿主自己的界面。

## 重审条件

- 宿主提供主题层接口时改接宿主的（D30 已带着这一条）。
- 皮肤中心提供可注入的主题服务时，判定改走服务，属性只留作第一帧的先验。
- ds-bot 公开模式的读写接口时，切换改用它，删掉对它类名与菜单顺序的依赖。
