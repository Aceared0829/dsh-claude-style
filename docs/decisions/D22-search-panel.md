# D22. 搜索面板：宿主的 Modal、宿主的数据与导航

- **状态**：已实施
- **分组**：功能
- **关联**：D11、D16

## 决定

- 放置：搜索框的位置由偏好决定，三档，取值写到文档的属性上供样式表分流。`overlay`（默认）把搜索框插在宿主品牌行里、品牌旁边，随鼠标移入淡出；`standalone` 在品牌行下方插入皮肤自己的一行，一直显示；`icon` 不画皮肤的搜索框，让宿主自己的搜索按钮留在原处，只接管它的单击。三档都只在品牌行带宽版品牌时放置。
- 快捷键：宿主的搜索快捷键没有可替换的公开入口，它的效果只是展开宿主自己的侧栏搜索并聚焦输入框。这块搜索因此保持挂载，`overlay` 与 `standalone` 下只从视觉与布局里拿掉，`icon` 下留在原处；焦点落进它的输入框时面板打开，由宿主自己的清除按钮收回，快捷键改绑后也跟着走。
- 面板用宿主自己的模态外壳：遮罩、焦点归还、Esc 与模态层都由宿主负责，卡片里的行由皮肤搭。它不套 D16 的弹层外壳，但登记进弹层互斥表。宿主的模态关闭即卸载，所以关闭时先给遮罩层打标记、保持挂载淡出，淡出结束后再卸载，标记在卸载之后才撤，否则会重播一帧入场动画。
- 数据全部读宿主的客户端服务：会话与工作区清单（去掉已归档、子代理与空白占位）、插件清单与管理、当前会话的 Skill、快捷键目录。远程命名空间在面板打开时经上下文按名字读取，在根上下文直接读远程的子属性会被 cordis 以「没有 inject」拒绝。
- 导航用宿主自己的入口：打开与新建会话、打开插件包、选择面板，Skill 经会话输入写草稿并聚焦，设置页与快捷键列表经它们在插槽登记里声明的存储打开。快捷键行只打开快捷键列表，不代为执行命令，宿主的快捷键命令没有公开的执行入口。内容命中还要落到那条消息所在的一轮：面板开完会话，等这一轮进了窗口再按命中消息的事件序号定位，跳转本身走 D34 那一套、按宿主的刻度跳。
- 匹配沿用宿主侧栏搜索的子串规则，排序为：标题开头、标题中的词开头、标题其他位置、第二个键（路径、包名、描述、别名）。
- 消息内容由宿主半边的一条私有路由搜：日志按 id 经宿主的观察接口读，不先列整份存档；只收人类发出的消息与助手消息里的 text 块，注入的环境快照、Skill 目录、AGENTS.md 与压缩检查点，以及推理、工具调用与工具结果，都不进语料；匹配沿用宿主自己的过滤规则，字面、不分大小写、空白可伸缩。
- 每个会话的语料在缓存目录里落一份并记修订号：热启动只重读修订号变了的存档会话，宿主开着的会话只读新增的那一段。存档会话的清单要逐个打开日志的头部帧，是这条路上最贵的一步，每 2 秒最多列一次，由面板打开时那次不带查询的预热承担，打字查询不列。每个会话只回最新的一处命中，附摘录与命中位置。

## 理由

- 面板要做的每件事宿主都已有一条路，借用这些路，行为与宿主各处一致。
- 位置属于读者的口味，三档的行为一致：品牌行里的搜索框会盖住品牌，有人要宿主自己的图标、有人要一个一直看得见的框，所以做成三档偏好，三档共用同一个面板。
- 内容搜索是唯一的例外：宿主的索引 `sessions.search`（SQLite FTS5）在出厂 Web 组合里关闭，它的 `unicode61` 分词搜不到中文句中的字；读日志与匹配规则仍用宿主的。

## 代价

- 依赖上面这些服务、store 与品牌行结构的现状；数据与导航要在真实页面核对。
- 内容搜索在一台还没有语料缓存的机器上，第一次搜索要读完全部会话日志（本机 260 个会话一次约 1 分钟）；此后每次宿主进程启动读一遍语料文件约 1.4 秒，单次查询约 5–20 毫秒。语料按会话落盘（本机约 6 MB），内存里另有一份小写副本。存档会话的清单每 2 秒最多列一次，列一次约 1.3 秒（要逐个打开日志的头部帧），由面板打开时的预热承担，打字查询不列。

## 重审条件

- 宿主提供自己的全局搜索或命令面板时改为打开宿主的；宿主的内容索引能按子串匹配中文、并在出厂组合里打开时，内容搜索改回 `sessions.search`。
