# D32. 搬来的聊天区交互：自己的前缀、自己的偏好、对上游让位

- **状态**：已实施
- **分组**：功能
- **关联**：取代 D23、D55、D56、D57、D58、D63；D26、D29、D40、D41、D44、D62
- **迁移**：聊天区契约表并入契约模块（D44，待实施）

## 决定

- 从上游聊天插件搬入的聊天区交互（token 淡入、思考行与过程组自动开合、卷帘门过渡、增强跟随、组体跟随、文件变更行、插入符动效、聊天气泡动效、过程组标题上的计数、说明模型正在做什么的那一行）分目录放在各自的功能目录里。推理期间思考行里的回放窗口也搬自上游，与状态行文字交替、计数数字滚动一样属于搬来的动效。
- 它们只读宿主自己写的属性；聊天区的整份宿主契约（流式容器、工具调用行、过程组、思考行的推理正文槽位、会话滚动条、输入框与回显气泡等）集中在契约模块的一张表里（D44）。
- 功能自己写出的标记（DOM 标记、类名、自定义属性、关键帧名称）一律用皮肤自己的前缀，与上游包同时装着时两套实现读不到对方的状态。
- 不止读标记的三处：
  - 文件变更行接管宿主工具调用视图上编辑与写入两个键位，优先级低于宿主自己那两个；改动派生与宿主的卡片模型只差「不排除子调用」这一条；同一个文件在同一个过程组里的多次改动读成一行（D62）。
  - 聊天气泡动效在 `<body>` 末尾挂一个临时替身，对辅助技术与焦点不可见，摘掉身份标记、保留样式钩子；飞行期间把真实那一行藏起来但保留布局盒，到达后真实行先显示、替身淡出。
  - 增强跟随在流式输出期间接管会话滚动条的跟随：宿主每次内容增长都把位置写到最底，跟随在同一帧绘制之前把这次位移撤回、交给滚动主人（D41）滑过去。浏览器的观察回调按建立先后调用，所以跟随的观察者每遇到一条新的消息列就重建一次，排在宿主之后、观察同样的元素。跟随期间把宿主自己的「回到底部」按钮临时藏起来，只写皮肤自己的标记，宿主的状态不动；读者自己发出的消息到达时跟随让开一段，宿主把新消息滚进视野的那一下照旧一步到位。
- 设置：这些功能共用皮肤自己的偏好条目与设置页，不动上游插件的配置。对话区各项共用一个开关（「聊天区动画效果」）：开启时安装，关闭时这些功能一起卸载、各自把界面交还宿主。新文字淡入与光标动画各有自己的两档：前者「淡入」与「直接出现」，后者「开」与「关」。各功能的清单声明自己挂在哪个偏好上、在一项选择偏好的哪些取值下运行（D42）；随偏好出现的样式规则由功能把标记写到 `<body>` 上。
- 对上游让位：页面装着上游时这些功能整体让位，判定读宿主启动清单里的条目，也读上游留下的样式表节点；设置页把三行控件禁用、保留读者的值，下面以强调色写明由谁接管。让位由清单声明（D42），入口统一执行：上游在页面上时这些功能不安装，上游中途装卸会立刻卸下或装回，重跑一遍偏好监听，功能内部不再自己判断。
- 过程组标题的计数摘要是皮肤自己在宿主标题控件末尾接的一段：四项数字按过程组内部的行种类在每次变动后一帧重算，思考、助手输出、工具调用与其余记录各算一类。容器放得下时写成整句，放不下改写紧凑形式、宽回来再换回，可访问名字始终是整句；宿主那句活动清单在摘要站住时由样式表隐藏。
- 说明模型正在做什么的一行是皮肤自己在宿主运行行的文字之后接的一段：说法只由一处给出，写上之后锁住一小段、锁过写当时最新的状态，中间不补演，被锁跨过去的调用说法在锁一过先补上。同一内容容器出现可见且非装饰性的替代文字时按归属让位，撤下皮肤自己的文案、计时与徽标，不读第三方插件名称。对话还在跟随末尾时宿主那一行固定在输入框上方，读宿主自己的跟随标记与皮肤的持有标记；已停止与失败的轮次不改写，宿主自己的控件留在原处。
- 动画效果读减少动态效果的判定（D26），样式表一侧以 `<body>` 上的动画属性为门控。
- 没有搬的一处：上游会把网页端「工作步骤展示」的缺省档位改成「标准」。本仓库不代写宿主自己的设置；网页端默认档位（「详细」）下组体不封顶，自动开合与组体跟随在那两处不发生，读者选到「标准」或「简洁」后生效，README 写明这一点。

## 理由

- 上游的属性名原样保留时，两套实现同时装着会互相认领对方的标记；只换前缀不足以共存——两套卷帘门会互相回放同一次点击，两套自动开合各点同一个开关，文件变更行两边同优先级注册同一键位会抛错，所以必须整体让位。
- 跟随的观察者若在安装时建好一直沿用，就排在宿主之前：宿主那一下每帧都画出来，下一批文字到达时跟随又把已经画出来的位置拉回去，画面忽而上跳、忽而下掉。
- 计数摘要与等待行读宿主已经画好的行与聊天快照，不需要会话投影；运行中的说法归等待行一处之后，读代码的人不必再分辨哪一半还在生效。
- 新文字淡入默认「直接出现」：输出滚动期间新到的字符大多落在滚动层下方，淡入在读者眼前几乎看不出变化，所以它作为一项可选项留在「动效」页，需要时打开。

## 代价

- 上游的更新要人工对照搬运；行为由本仓库自己的测试覆盖，包括一个上游在场的让位用例。
- 计数与读数按宿主过程组的行种类与属性来数，宿主编排过程组的方式变了要跟着改；这些选择器与属性进了契约表，由契约场景与端到端场景在真实宿主上核对。宿主的快照不给工具结束时刻，工具跑完之后的等待比实际略短。
- 已停止与失败轮次的用时与输出 tokens 不再显示，历史里的这些轮次只剩宿主自己的「已停止」「处理失败」。

## 重审条件

- 上游把这几项拆成可依赖的库并公开稳定接口，或宿主自己把这些交互收成正式能力时，改为依赖而不搬运。
- 宿主把过程组的计数、时长或运行状态放进公开数据时，计数摘要与等待行改读宿主的值，不自己数、不自己判定。
- 读者要求本插件提供阅读视图或恢复停止轮次的排列时，按 D43 认可的扩展点重新登记一份，不恢复旧实现。
