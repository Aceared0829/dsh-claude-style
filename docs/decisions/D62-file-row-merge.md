# D62. 同一文件的多次操作读成一行

- **状态**：已实施
- **分组**：功能
- **关联**：D5、D9、D26、D32、D66、D51

## 决定

- 读取、编辑、写入三个工具都从 `tool.call.toolview` 按自己的键（`read`、`edit`、`write`）在优先级 -1 上接管宿主自己的行，三个键一起注册、一起释放。
- 同一个过程组内容层里，同一个文件的多次操作读成一行：这一行是这一组里文档顺序最早的那一次调用，行首的图标与标题是这一组里最后一次操作的样子（读取 / 编辑 / 写入），行尾的 `+n -m` 是这些改动的累计值，展开读到的是全部改动；只被操作过一次的文件按原来的样子画一行。
- 文件的工作从一种操作走到下一种时，行首就地换新：旧的那个向上离开并模糊、新的自下升入（transitions.dev 的「Text states swap」，MIT，与运行行换用词是同一段片段）。两态同处一个网格单元，所以标题盒子取较宽的一态、旁边的路径不左右移动。动画档为「减弱」时直接写入新状态（D26）。这是这套片段的第二处使用，第三处出现时按 AGENTS.md 的停止线移进 `packages/client/src/shared/`。
- 行尾数字只数改动：这一组只有读取时没有行尾数字。每个字符各占一个自己的盒子，只有自己的数字变了的字符才翻页，旧的向下转出、新的自上方转入，其余字符原地不动，数字长大读起来是一个数字在翻。
- 翻页的盒子用 `clip-path: inset(0)` 裁掉溢出的部分，`overflow` 会把行内块的下边缘当作基线、把字形抬离同一行的文字基线；`perspective` 开在盒子上，翻页在自己的格子里发生。动画档为「减弱」时直接写入新数字（D26）。这是仓库里第二处翻页数字，第三处出现时按停止线移进 shared。
- 展开这一行读到的内容按同一顺序取：这一组有改动时是全部改动的卡片；只有读取时是最后一次读取的窗口（`primitives.ReadBlock`，与宿主自己的读取卡片同一档）；两者都拿不到时退回皮肤已有的 IN/OUT 文本卡。
- 读取的窗口先从结果自带的元数据读（`meta.path/offset/lines/totalLines/lang`，形状与范围照宿主读取卡片模型收严），元数据缺失时——程序派发的子调用不持久化元数据——从结果文本的模型可见信封里读回来（编号行加一条页脚给总数）。
- 每个文件行把自己的路径、操作与它自己那一次调用的改动登记进这次安装自己的一张登记表（`packages/client/src/features/chat-files/file-row-merge.ts`），代表行从表里读回整组的内容。代表权按文档顺序决定，新调用到达时代表行留在原处，只有行首的操作、数字与卡片变化。
- 登记按调用记，不按行元素记：宿主给直接调用的是内容层自己的那一行，并把这个元素交给这个文件的下一次调用。行元素带着自己的调用 id：新的 id 往这个文件的累计上添一次，同一个 id 就地换掉自己上一次登记，读取因此不会让行尾清零。
- 被代表的行整行离开页面：标记按 D9 写在宿主给这一次调用的那个盒子上，宿主在它周围留的间距随之消失，样式用 `display: none`。直接调用的工具站在自己的流式块（`data-chat-flow-key`）里时标记写在这个块上：有的宿主版本给每个流式块上下各留一段外边距，只藏块里的调用行，外边距会留在原处，内容层是纵向 flex，外边距不折叠，藏掉几行就叠出几段空白。程序派发的调用与程序自己的调用同在程序的流式块里，标记写在子调用自己那一行，程序那一行留着；宿主没给调用单独的块时写在调用行上。失败与中断的行不登记。
- 合并后的行多一句视觉隐藏的说明（`fileRowMergedOperations`），读屏念到的是这一行代表的全部调用。
- 合并挂在文件行已有的开关上（`chatAnimations`，D29/D32）：开关关掉时这些行一起交还宿主，不新增偏好。

## 理由

- 宿主每次调用画一行，同一个文件读几次、改几次就出现几行，读者要在整段过程里找出这个文件的每一次调用；读成一行之后，读者看到的是这个文件一共做了什么、被改了多少。
- 行首跟着最后一次操作，正是读者想知道的那件事：这个文件此刻在被读还是在被改。文件已经读成一行，行首比新增一行更适合说这件事，页面上也不再出现同一文件的重复行。
- 行尾数字与改动卡片读同一组改动内容，数字与卡片不可能对不上；代表行取最早的一行，数字增长时这一行不移动位置。

## 代价

- 读取行改由皮肤绘制（图标、标题、路径、展开的读取卡片），应用里所有读取行都换成皮肤的样式；读取窗口按上面两条路各取一次。
- 只有读取的一组不显示改动数字：这个文件被读过由行首的操作与展开的窗口说清，行尾不出现数字。
- 英文两态的标题宽度不同，横向的差由网格单元吸收：标题盒子取较宽的一态，旁边的路径在换新前后不动，但会比窄的那一态多出一点空隙。
- 被代表的行上各自的「轨迹入口」按钮不再可点，它们的改动内容通过代表行展开后的卡片读到。
- 代表权依赖行的文档顺序与挂载状态：长会话把离屏的行卸载时，代表权落到剩下的最早一行。

## 重审条件

- 宿主自己把同一个文件的多次操作画成一行、并把行首的操作交出来时，改为读宿主的。
