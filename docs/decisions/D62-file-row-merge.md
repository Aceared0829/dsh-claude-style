# D62. 同一文件的多次改动读成一行

- **状态**：已实施
- **分组**：功能
- **关联**：D9、D26、D32、D45

## 决定

- 同一个过程组内容层里，同一个文件的多次编辑与写入读成一行：这一行是这一组里文档顺序最早的那一次改动，行尾的 `+n -m` 是这些改动的累计值，展开读到的是全部改动的改动卡片；只改动过一次的文件按原来的样子画一行。
- 每个文件改动行把自己的路径、改动内容与状态登记进这次安装自己的一张登记表（`packages/client/src/features/chat-files/file-row-merge.ts`），代表行从表里读回整组的内容。代表权按文档顺序决定，新改动到达时代表行留在原处，只有数字与卡片增长。
- 被代表的行整行离开页面：标记按 D9 写在宿主这一次调用的行上（直接调用的工具是内容层的子元素，程序派发的调用是它自己那一行），宿主行的间距随之消失，样式用 `display: none`。失败与中断的行不登记，保留自己的裁决信息。
- 行尾数字按过程组标题计数数字的时长与曲线滚动（160ms，`cubic-bezier(.16, 1, .3, 1)`）：每个字符各占一个自己的盒子，只有自己的数字变了的字符才向上翻，其余字符原地不动，数字长大读起来像里程表。盒子用 `clip-path: inset(0)` 裁掉溢出的部分，因为 `overflow` 会把行内块的下边缘当作基线，而盒子只有一字高，字形会被抬离同一行的文字基线。动画档为「减弱」时直接写入新数字（D26）。这是仓库里第二处滚动数字，第三处出现时按 AGENTS.md 的停止线移进 `packages/client/src/shared/`。
- 合并后的行多一句视觉隐藏的说明，读屏念到的是这一行代表的全部改动。
- 合并挂在文件变更行已有的开关上（`chatAnimations`，D29/D32）：开关关掉时这些行一起交还宿主，不新增偏好。

## 理由

- 宿主每次调用画一行，同一个文件改几次就出现几行，读者要在整段过程里找出这个文件的每一次改动；读成一行之后，读者看到的是这个文件一共被改了多少。
- 行尾数字与改动卡片读同一组改动内容，数字与卡片不可能对不上；代表行取最早的一行，数字增长时这一行不移动位置。

## 代价

- 被代表的行上各自的「轨迹入口」按钮不再可点，它们的改动内容通过代表行展开后的卡片读到。
- 代表权依赖行的文档顺序与挂载状态：长会话把离屏的行卸载时，代表权落到剩下的最早一行。

## 重审条件

- 宿主自己把同一个文件的多次改动画成一行时，改为读宿主的。
