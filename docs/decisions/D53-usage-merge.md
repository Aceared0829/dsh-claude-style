# D53. 用量账本：两个来源按日期合并，本地记录活过会话日志

- **状态**：已实施
- **分组**：运行时
- **关联**：D11、D12
- **现状**：本条改写「账本只在它覆盖最新会话活动时被采用」的旧规则，并收下原先只当缓存用的本地那本账：它记在插件自己的目录里，日志删掉之后它是那些日子唯一还在的地方。此前只要账本的最新一天早于最新一条会话活动（成本计量插件停写就会出现），整份账本被丢弃，面板改用本地折算；本地的那份又随会话日志的删除一起变小。

## 决定

- 成本计量插件的账本与本地折算（`usage.ts`、`usage-fold.ts`）是同一批日子的两本账，按日期合并，绝不按金额相加：账本认识的一天就是账本的一天，只有账本最新一天之后的日期来自折算。
- 本地那本账记在 `$DSH_HOME/dsh-claude-style/usage.json`，与读者的字体、品牌图同处一地，不放 `cache/`：那一处随时可清，而它要活过它记的那些日志。
- 日志已不在的会话，它的日子原样留在记录里：面板照旧给出这些日子的 tokens、模型与小时直方图。这些日子是它们唯一的账，折算再也补不出来，删掉对话不再让用量变小。
- 记录里每个会话存它的日志指纹（大小与修改时间），日志不在时不存：没有什么再和它比对，也没有什么要跳过。
- 记录里一天的量按路由存放（模型，以及没有归到任何模型的余量），当天的总量由这些路由相加得出；小时直方图只记非零的格子。
- 记录的版本不是本版所写时不覆盖它，只记一条警告：那是知道得更多的版本写的。本版之前的那一份是折算缓存，记在 `cache/dsh-claude-style/usage.json`，记录不存在时迁移一次。
- `totals` 按合并后的日图重算，`sessions` 取两边会话 id 的并集（账本每天的会话 id，加上折算那几天各天自己的会话 id，日志已删的会话也在其中），`activeDays` 是合并后的天数。
- 路由先把账本自己算出的结果交出去（`publish`），折算完成后换成合并结果，所以账本再旧也能立刻显示它覆盖的全部历史。
- `source` 在折算补进过日期时写 `cost-meter+local`，完全没有账本或账本补不上时写 `local`；两个值都不改变面板的取数路径。
- 折到账本已覆盖日期的会话照旧留在记录里，读它们的账本日不与之相加。
- 账本不存在、解析不了或版本不认时，整条路径与从前一致：只用本地折算（D12）。
- 记录只在与它不同的那一趟写回：有会话重新折算、有新的会话、有会话从记录里消失，或某个会话的日志不见了（它的指纹随之去掉）。
- 一个会话的日志经宿主的观察接口读（`sessionQuery.observeSession`，见 `session-events.ts`）：它只按 id 观察这一份存档，不先列整份存档，所以读 N 个会话是 N 次观察、零次列档；宿主只发布 `readSession` 时退回按 id 读，那一版每读一个会话会先列一次整份存档。

## 理由

- 两本账说的是同一批日子：相加等于同一批结算被计两次，丢弃等于拿日志还在的一部分去顶替全部。
- 折算的依据是会话日志，日志一删那笔账就没了：面板上「全部」的数字随删对话一起变小，读者读到的是错的。
- 记录存的是读者唯一还可能失去的那笔历史，且只存折算得出来的几样：当天的总量等于它那些路由之和，存第二遍只是把同一批数字写两处。

## 代价

- 记录不能再「坏了就重算」：格式升级要写迁移，认不出的版本只能留在那里，等写下它的那一版回来。
- 折算仍要遍历全部会话日志，成本由记录里的指纹摊平（只有变更过的日志重读）；一趟里每个变更过的日志各观察一次，观察按存档修订号复用已还原的会话。
- 一个会话在账本覆盖的日子里结算过、又在未覆盖的日子里结算过时，会话数会重复计一次；账本的会话 id 与会话目录名格式不同，无法相减。
- 「高峰时段」只由折算补上的那几天决定：账本没有小时维度，它覆盖的日子在被折到之前没有直方图，窗口的峰值可能因此偏低。

## 重审条件

- 宿主发布跨会话的用量总量（不必再读别的插件的文件）时，改为只读宿主。
- 宿主自己保留已删会话的用量时，删掉记录里「日志不在也留着」这条路径。
- 成本计量插件不再维护账本格式时，删掉这条路径。
