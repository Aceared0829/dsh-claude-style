# D68. 会话工作树：工作树与分支只用于协调改动

- **状态**：待实施
- **分组**：分发与流程
- **关联**：D66
- **现状**：并行会话共用主树，提交按「只提交自己的改动」的补丁纪律维持；会话分支推送到远端后由云端整轮判定，本地判定跑在会话分支上，合入主分支与删除分支靠人工收尾，工作树与分支长期残留。

## 决定

- 每个会话在主树执行 `npm run session -- start <名字>` 开工：脚本在 `.claude/worktrees/<名字>` 建工作树、开 `session/<名字>` 分支、把 `node_modules/` 联接（junction）到主树那一份；此后编辑、构建、实测页面全部落在该树。主树的源码文件会话不碰，只在收尾合入时由 `finish` 改动。
- 工作树与 `session/` 分支只用于协调改动：一棵树一个会话，互不干扰；分支只存在于本地，不推送远端（向外部项目提 PR 时除外）。云端不为会话分支启动运行，因为那条分支上没有交付物。
- 会话树里不跑测试：`npm run verify` 及其各档只在主树运行，判定属于将被推送的那棵树。树里可以做的是构建与实测页面（迭代期的验证手段，D66）。
- 收尾由 `npm run session -- finish` 完成，它在工作树内执行：确认树内无未提交改动、主树在 master 上且干净，随后在主树把会话分支合并进 master（`--no-ff`，合并提交题名取自该分支最后一次提交），在主树取本次推送的推送前判定，通过后推送 master。判定失败不推送，修复在主树进行。
- 分支与工作树在合并之后删除：`npm run session -- sweep` 从主树收走工作树，并删除已合入 master 的 `session/<名字>` 分支。会话树里禁止 `npm install` 与 `npm ci`：联接会让两者删穿主树的真实目录。
- 判定归属：master 上的云端失败由最后推送它的会话修复；属于别的分支或外部 PR 的运行，在回复中报告归属、不动手。

## 理由

- 云端只判定 master、PR、合并队列与手动运行：为会话分支推送的整轮运行没有对应的交付物，rebase 之后还要重跑一次。
- 判定与交付物同处一棵树：结论读到的树就是将被推送的树，避免「结论属于分支、交付物属于 master」的错配。
- 分支短命让分支列表等于未完成工作清单：合入即删除，工作树由 `sweep` 收走，残留不会积压。
- 工作树不复制 `node_modules/`，独立安装一次以分钟计；联接复用主树已装依赖，开工成本降到秒级，而 Node 只读加载使多树共享一份目录无并发问题。

## 代价

- 合入之后闸门若失败，master 上留有未推送的合并提交，修复在主树进行，`finish` 不再自动还原。
- 主树的判定与推送成为收尾的串行点：多会话同时收尾时按判定锁（D66）排队，先到的先推送。
- 联接把「禁止在会话树里装依赖」变成一条必须遵守的红线，违反的代价是主树依赖被清空。

## 重审条件

- Git 或 npm 提供官方的工作树共享依赖机制时改用它；宿主提供多会话协作的官方扩展点时重审整条流程；远端提供本地合并队列时重审判定与推送的先后。
