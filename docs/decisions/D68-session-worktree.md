# D68. 会话工作树：每个会话在自己的树与分支上工作

- **状态**：待实施
- **分组**：分发与流程
- **关联**：D66
- **现状**：并行会话共用主树，提交按「只提交自己的改动」的补丁纪律维持；会话间改动互相覆盖、测试锁排队、判定读到他人半成品、远端失败无人认领。

## 决定

- 每个会话在主树执行 `npm run session -- start <名字>` 开工：脚本在 `.claude/worktrees/<名字>` 建工作树、开 `session/<名字>` 分支、把 `node_modules/` 联接（junction）到主树那一份；此后编辑、构建、本地判定全部落在该树。主树的源码文件会话不碰，只在用户明确指示时用于合并 `session/` 分支。
- 会话工作树里禁止 `npm install` 与 `npm ci`：联接会让两者删穿主树的真实目录。依赖变更在主树做，做完联接继续生效；`start` 发现两树锁文件不一致时拒绝开工，任务本身是锁文件变更时用 `--deps` 显式豁免。拆除工作树前脚本先删掉这个联接（`removeTree`）：Windows 把联接报成目录，递归删除会走进主树、连着主树 `packages/*` 一起删；树里另有指向自己的链接时拒绝拆除。
- 判定归属：会话判断自己改动的唯一动作是把提交推上自己的分支并读云端结论（D66 的快档）；本地只跑覆盖本次改动的最小集合。云端失败的认领按分支：失败的 run 的 `headSha` 属于本会话推送的提交，由本会话修复并推同一分支；属于别的分支或 master，在回复中报告归属、不动手；master 上的红由用户在主树发起专门修复。
- 收尾：会话结束时在工作树内执行 `npm run session -- finish` 推送分支（工作树留到会话退出后，由主树的 `npm run session -- sweep` 收走：无存活属主、无未提交改动、无领先提交的树才清理）。AGENTS.md 的「只提交自己的改动」补丁纪律随本条生效而废止。

## 理由

- 树共享是四类冲突的共同根源：文件系统视图独立之后，改动打架、锁排队、测到他人半成品同时消失，每棵树的锁与结论缓存成为会话私有。
- 工作树不复制 `node_modules/`，独立安装一次以分钟计；联接复用主树已装依赖，开工成本降到秒级，而 Node 只读加载使多树共享一份目录无并发问题。
- 分支即归属让远端失败有了唯一负责人：谁推送的提交引发的红就是谁的修复任务，其余会话不再巡检与己无关的运行。

## 代价

- 每棵树首次 `npm run build` 要重建自己的 `lib/`；各树的判定缓存互不复用，同一改动在两棵树各跑一次的结论要各付一次。
- 联接把「禁止在会话树里装依赖」变成一条必须遵守的红线，违反的代价是主树依赖被清空。

## 重审条件

- Git 或 npm 提供官方的工作树共享依赖机制时改用它；宿主提供多会话协作的官方扩展点时重审整条流程。
