# D29. 功能开关：每个功能声明开关或不设开关的理由

- **状态**：已实施
- **分组**：运行时
- **关联**：D12、D42

## 决定

- 每个功能在自己的清单（D42）里二选一地声明：挂在哪个偏好键上，或一句不设开关的理由。两个都写由类型拒绝，两个都没写、或声明的键不在宿主半边的偏好缺省表里，由构建拒绝。
- 划分标准：替换或挪动宿主原有的控件与区域、或往界面上加新的可见元素的功能设开关；不设开关的是读者什么都没提供时页面与宿主一致的、从属于另一个已有开关的，以及设置页本身。几个功能可以共用一个开关，也可以共用一个选择项的不同取值：搬来的几个聊天区动效同用一个，模型选择器与推理强度同用一个，对话区统计在自己的位置项下运行，禁用词在语言项下运行、取值关闭时不安装。
- 属于偏好缺省表的开关统一执行：启动时关着的功能不安装；选择项按清单里声明的取值判定，取值不在其中就是关。偏好每次被采用时逐个功能对照，关掉就运行它自己的拆卸、删掉句柄、交还接管的宿主界面，打开就重新安装，都不刷新页面。其余的偏好由功能自己读。退役过的功能（D12）在本代内不因偏好变化装回。
- 设置页按分页组织（通用、外观、输入区、侧栏、对话、桌面端、动效）。布尔开关的行由拥有这个偏好的功能在清单里声明分页、序号与文案键，共用一个开关的几个功能只由其中一个声明；其余的行与控件来自另外两处，按序号合并。从属于另一项的行紧跟在它下面、两行之间不画分隔线，父项关闭时变灰、不能操作。「桌面端」页放只作用于 Windows 桌面端窗口的开关；偏好在宿主的设置文档里、各页面共用，所以别的页面上这些行照常可改，分页开头一行说明改动在 Windows 窗口里生效。「动效」页放不属于任何单个功能的动效选择，与「通用」页的动效开关分开：后者是减弱与否，前者是在同一个减弱规则下换一种画法。
- 功能只在另一个偏好的某些取值下起作用、而它的行与那一项不相邻时，清单的开关行声明那个偏好、起作用的取值与一句说明：那个偏好不在这些取值里时，这一行保留读者存下的值、控件不能操作，说明下面用强调色写出它在等哪一项。

## 理由

- 新功能登记时就要回答「读者能不能关掉它」；开关的语义统一为「关掉 = 宿主原样」，每个功能的 teardown 本来就负责交还宿主界面（D12），开关只是在运行中调用它。
- 不起作用时仍能切换的行，读者切了看不到变化；依赖写进清单，设置页才能照实显示哪一行此刻起作用。

## 代价

- 每个功能的 teardown 必须能在运行中途执行并完整交还宿主界面，测试逐项核对开关打开与关闭两种状态。

## 重审条件

- 宿主提供插件级的功能开关或按区域停用插件的机制时，改接宿主的。
